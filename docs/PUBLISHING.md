# 公开仓库上传说明

公开上传包括源码、合成示例、测试、依赖锁文件、数据库迁移、环境及进程脚本、部署模板、字体及许可证、开发和验证说明。便携工具和 `node_modules` 不随源码分发；克隆后按 README 安装。

以下只留在本机，禁止使用 `git add -f` 上传：

- `.runtime/`：随机凭据、临时数据库、PDF、项目备份、浏览器配置、日志和测试输出。
- `.tools/`、`.cache/`、`node_modules/`、`dist/`、Java `target/`：工具、缓存和生成物。
- `.env`、真实部署配置、证书及私钥、IDE/云账号/代理配置。
- `.backups/`、`.workspaces/`、旧方案、历史测试截图与任何实际用户 SQL、数据库备份或原生项目文件。

`deploy/.env.example` 只包含明显占位符；实际值通过 `node scripts/create-deployment-env.mjs` 在本机生成，不能提交。日志和截图同样可能含有用户数据，不能因为没有密码就认为可以公开。测试使用合成数据，产生的证据保存在忽略目录，不随仓库发布；旧验证文档中的本地证据路径不是公开下载链接。

每次上传前：

```sh
git status --short
git add <已审查的源码和文档>
npm run check:publication
git diff --cached --stat
git diff --cached --check
```

检查脚本读取 **Git 索引内容**，拒绝禁传路径、私钥和常见令牌，检查个人路径与邮箱；本机存在随机凭据时只在内存中比对，绝不输出凭据。它不能识别所有敏感数据，必须结合人工审查。Git 未在 PATH 时可在当前进程设置 `GIT_EXECUTABLE` 为已安装的 Git，不更改全局配置。

提交也使用 GitHub 隐私邮箱。首个提交之前完成检查，避免敏感信息进入历史；发现已上传凭据应立即轮换，随后清理历史，单纯删除文件无法撤销泄漏。

发布前从干净克隆执行 `npm ci`、单元测试、生产构建和 `npm run test:smoke`。完整服务另跑 Java 与浏览器回归，记录实际结果。检查远程仓库可见性、文件清单与提交一致，确认没有把本地工具及运行目录传上去。CI 不使用生产凭据，不部署服务器。

当前项目整体许可证尚未确定，不自动添加 MIT 等授权。第三方版权与字体许可证必须保留。
